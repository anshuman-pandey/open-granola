# Synthetic LM Studio API observations — 9 November 2026

This is maintainer-operated API evidence, not independent adoption, desktop validation, or a release certification. No microphone, library, private chat, or meeting content was submitted. Requests used the original synthetic English passage in `docs/integrations/VALIDATION.md`.

Environment: LM Studio 0.4.26+4, Apple Silicon Mac with 16 GiB RAM, loopback server `127.0.0.1:1234`; local-network serving and CORS disabled. Model identities were read from the local model API. Both loaded contexts were 8,192 tokens. Requests used the app's summary system/user prompt construction, automatic output language, empty template, non-streaming Chat Completions and 1,200-token cap. Python submitted the API requests directly; the desktop provider/parser/storage path was not exercised.

| Same model, explicit types and assignment rules | 106.14 seconds; length finish reason and empty final content. Reasoning consumed the budget. Not a successful summary. |
| Ministral 3 8B Instruct 2512, Q4_K_M, original prompt during loading | Request timed out at 120 seconds. This is not evidence of a schema failure. |
| Same Ministral model loaded, explicit types and assignment rules | 66.04 seconds; stop finish reason and JSON with string decisions, Asha's explicit draft assignment and verbatim deadline. No invented budget assignment. The undecided budget was omitted from the summary/chapters, so completeness still needs improvement. |

A warm original-prompt control returned decision objects again and unexpectedly generated Swedish prose from the English sample. The final revision adds preservation of unresolved matters: its guide sample returned string decisions, the explicit Asha assignment with the spoken deadline, and an undecided-budget summary. The second no-assignment case kept the unresolved search question and returned no actions. It preserved the onboarding decision in chapters but omitted it from the decisions array. All 65 native library tests passed, including the reduced schema regression; formatting and privacy checks passed. Content completeness is still not established. One successful output does not establish reliability or causality. The LFM result remains a known failure; do not advertise it as compatible or extract its reasoning as final notes. No request timeout, token limit, parsing gate or release-validation requirement was weakened.

Next gates: repeat representative synthetic cases, run the actual desktop provider and saved-summary recovery, then microphone/install/export checks and independent first runs. A working API alone does not authorize a compatibility listing.
