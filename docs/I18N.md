# Languages and translation contributions

Open Granola separates the language of its interface, the language spoken in a recording and the language requested for generated notes. Changing one does not silently change the others or translate your existing library.

## Three independent choices

| Choice | Available options | What it changes | What it does not do |
|---|---|---|---|
| Interface language | English (`en`), हिन्दी (`hi`), Español (`es`), 日本語 (`ja`), 简体中文 (`zh-CN`), 繁體中文 (`zh-TW`) | Translated interface messages and locale-aware dates/numbers | Translate stored meeting content, native diagnostics, provider replies or all repository files |
| Transcription language | Automatic or one of the 27 codes below | The language supplied to local Whisper when a new capture begins | Enable cloud transcription, speaker identification or guaranteed mixed-language accuracy |
| Note language | Automatic/source language or one of the same codes | The requested language/script for generated note prose and commitment descriptions | Rewrite the source transcript or guarantee that a selected model follows the instruction |

The default UI language is English until a supported preference is saved. Missing UI messages fall back to English. Interface preferences use the browser/webview's `open-granola-language` local-storage key; blocked storage still allows a session preference. Speech/note preferences are native desktop settings in SQLite, default to `auto`/`auto`, and are reset by a full library purge. The browser preview cannot validate native recording or model behavior. If saved desktop language preferences cannot be read, the interface keeps them locked until a successful retry or an explicit reset to automatic. Library deletion reloads the preferences from native storage.

### Supported preference codes

The allowlist is shared by the UI and native validator in [language-options.json](../src/lib/language-options.json). These are accepted settings, **not 27 measured accuracy claims**:

| Group | Codes and languages |
|---|---|
| Languages also translated in the repository/UI | `en` English, `hi` Hindi, `es` Spanish, `ja` Japanese, `zh` Chinese |
| Other Indian/subcontinental language choices | `bn` Bengali, `ta` Tamil, `te` Telugu, `mr` Marathi, `gu` Gujarati, `kn` Kannada, `ml` Malayalam, `pa` Punjabi, `ur` Urdu |
| Other choices | `fr` French, `de` German, `pt` Portuguese, `it` Italian, `ko` Korean, `ar` Arabic, `ru` Russian, `tr` Turkish, `nl` Dutch, `pl` Polish, `uk` Ukrainian, `id` Indonesian, `vi` Vietnamese |

Use the exact codes. Regional tags such as `hi-IN` or `en-US` are not native preference values; the interface may use a regional locale for formatting separately. Adding a supported language requires checking the Whisper code, a suitable multilingual model, the catalog and relevant tests. It does not by itself add a UI translation or a translated README.

Simplified Chinese (`zh-CN`) and Traditional Chinese (`zh-TW`) are separate **interface and repository** translations. Recording and summary preferences continue to use the single Chinese code `zh`; choosing a Chinese interface does not request a specific script from Whisper or the summary model. Japanese uses `ja` in both places, with independent preferences.

### Recording and summary behavior

- Automatic transcription uses Whisper's language detection; an explicit choice supplies that code. Translation-to-English remains disabled. Automatic and non-English modes require a multilingual Whisper model; an English-only model requires the explicit English choice.
- Native settings reject unsupported codes and changes while a capture is active or waiting to be saved. Finish/save or discard that capture before changing its language settings.
- Automatic notes request the predominant transcript language and its original script. Mixed-language material asks the model to retain names and technical terms; this is an instruction, not a quality guarantee.
- Explicit note language applies to generated titles, summaries, chapter text, decisions and action descriptions. JSON keys and timestamp formats remain stable. Commitment evidence, deadlines quoted from the source and owner names stay faithful to the original.
- Summary retry uses the current note-language preference. A failed retry preserves the previous saved note and transcript. Processing history records the **requested** `summary_language`; older runs can have no language field. That metadata is not language detection or proof of output quality.
- These controls do not change the provider's destination or consent boundary. A cloud model still receives the relevant text only through the configured provider route. See [Privacy](../PRIVACY.md).

Implementation: [UI locale context](../src/i18n/index.tsx), [frontend language settings](../src/lib/language-settings.ts), [native validation](../src-tauri/src/language.rs), [Whisper configuration](../src-tauri/src/transcribe.rs), [note prompts](../src-tauri/src/llm.rs). The upstream [whisper-rs parameter documentation](https://docs.rs/whisper-rs/latest/whisper_rs/struct.FullParams.html) distinguishes automatic detection from translation, which only translates to English.

## Current coverage and limits

English source messages and Hindi/Spanish dictionaries live in [messages-workspace.ts](../src/i18n/messages-workspace.ts) and [messages-settings.ts](../src/i18n/messages-settings.ts). The [Japanese](../src/i18n/messages-ja.ts), [Simplified Chinese](../src/i18n/messages-zh-CN.ts) and [Traditional Chinese](../src/i18n/messages-zh-TW.ts) catalogs translate the same keys. [locales.ts](../src/i18n/locales.ts) registers the supported interface choices. Tests compare complete key sets and interpolation placeholders across all five translated catalogs.

The catalogs cover the workspace and settings surfaces wired to `useI18n`. Provider-supplied errors, raw native diagnostics, model identifiers, source meeting text and sample-library content can remain in their original language. Do not advertise the interface as exhaustively translated based on dictionary entries alone: strings must also be wired, visible and reviewed.

The repository translations are complete translations of the source documents listed below. Fluent human review is still welcome. No real multilingual microphone/model evaluation was performed for this documentation. Validate language quality with the [synthetic provider workflow](integrations/VALIDATION.md); distinguish transcription mistakes, note-language mistakes and UI translation defects in reports.

## Translate the interface

1. Open a [translation issue](https://github.com/anshuman-pandey/open-granola/issues/new?template=translation.yml) for a new locale or a wording/layout problem. Specify the exact version, screen and locale. Check for an existing effort first.
2. Translate the complete message, preserving `{placeholders}` exactly. Keep URLs, model IDs, filenames, provider names and command identifiers unchanged. Do not translate the typed confirmation token `DELETE` unless the confirmation logic, label and tests are deliberately changed together.
3. Use plain, natural language. Preserve negation, consent, destructive consequences, units and distinctions between local and remote processing. Avoid replacing a precise limitation with a more reassuring promise.
4. Use `t(...)` for interface text, including accessible labels, empty states and errors. Use the locale helpers for numbers/dates. Keep user-authored notes outside translation dictionaries. Reuse the supported plural helper rather than concatenating translated sentence fragments.
5. Register new interface choices and catalogs in `src/i18n/locales.ts`. Test narrow layouts at 320 px, keyboard use, focus indicators, dialogs, long messages, dark mode and 200% zoom. Hindi needs readable Devanagari glyphs and line spacing; Spanish often needs more width. Japanese and Chinese use locale-specific system font fallbacks and roomier display-heading line spacing; inspect glyphs and wrapping on each target OS. An RTL UI requires a deliberate layout review and is not enabled by adding Arabic/Urdu speech options.
6. Run `npm run check`. Include screenshots using synthetic content and request a fluent review. Passing key/placeholder tests is necessary but cannot judge fluency or every screen.

## Translate the repository

English `README.md` and `CONTRIBUTING.md` are the source documents. Keep each translation in `docs/i18n/<NAME>.<locale>.md`. Preserve the source order, code commands, linked evidence, development-preview status and planned-versus-implemented distinction. Correct relative paths for the nested directory and use explicit anchors when translated headings change navigation targets.

When the English source changes:

1. Compare it with the source commit recorded in the translation's HTML comment.
2. Update all affected paragraphs, tables, steps and limitations in each translation. Keep changes to the source's meaning separate from translation fixes.
3. Update the source commit and review date only after reviewing the full difference; do not mark an outdated document current by changing metadata alone.
4. Check every local link and preserved shell command. Request fluent review for any privacy, security or destructive-action wording.
5. If a translation cannot be updated with the source change, add a visible stale-translation note that links to the current English document, and file a focused follow-up.

## Shared terminology

| English concept | Hindi guidance | Spanish guidance |
|---|---|---|
| Transcript | ट्रांसक्रिप्ट / प्रतिलेख; the written speech, distinct from a summary | transcripción; distinguish it from resumen |
| Summary | सारांश | resumen |
| Action item | अगले काम / कार्य; an assigned next step | tarea; a concrete next step |
| Commitment | प्रतिबद्धता; an explicit promise or assignment | compromiso |
| Local provider | इसी डिवाइस का मॉडल/सर्वर; not an encryption claim | modelo/servidor en este dispositivo; no implica cifrado |
| Retention | डेटा रखने की अवधि; explain when older notes are deleted | conservación; explain when older notes are deleted |
| Browser demo | ब्राउज़र डेमो; clearly identify sample data | demostración en el navegador; identify sample data |

Prefer consistent, understandable wording over literal word-for-word substitutions. Report uncertain terminology rather than inventing a feature or changing the privacy promise.
