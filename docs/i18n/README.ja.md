**開発中のプレビューです。** Open Granola はマイク音声を録音し、ローカルの Whisper で文字起こしを行い、ローカルモデルまたは自分で接続したプロバイダーを使ってノートを作成します。ライブラリはローカルの SQLite データベースに保存されます。クラウドで要約する場合は、文字起こしのテキストを選択したプロバイダーへ送信します。

システム音声の録音は未実装です。このビルドでは、ヘッドホンで聞いている通話相手の音声は録音できません。実際のマイクとモデルを使ったセッション、プロバイダーのアカウント、配布用にパッケージ化したリリースについては、対象のハードウェアで一連の動作を検証する必要があります。ブラウザプレビューでは、サンプルであることを明示した会議を使用します。

<a id="what-is-implemented"></a>

## 実装済みの機能

- **マイク音声の文字起こし：** ローカルの `whisper.cpp`、タイムスタンプ付きの文字起こしの区間、画面に表示されるライブ文字起こし。
- **要約プロバイダーの選択：** 内蔵 Qwen、LM Studio、OpenAI API、Claude API、カスタムの OpenAI 互換エンドポイント、実験的な「ChatGPT でサインイン」。
- **接続テスト：** テスト用のテキストを送信し、会議の内容を送らずに選択した要約モデルを確認します。マイク録音や Whisper のテストではありません。
- **保存済み会議からの復旧：** 要約する前に文字起こしを保存します。要約に失敗しても、再録音せずに再試行できます。ノートを再生成しても、既存のアクション項目の ID と完了状態は保持されます。
- **処理の詳細：** 保存した会議には、設定されたモデルとプロバイダーの処理経路、要約の状態が記録されます。あとから設定を変更しても、そのノートをどのように生成したか確認できます。
- **ローカルライブラリ：** キーワード検索、検索で取得したテキストに基づく質問、アクション項目、約束、Markdown のレシピ、JSON インポート、Markdown エクスポート。
- **保存期間の管理：** 保存期限を過ぎた会議の削除や、ローカルライブラリ全体の削除。制限については[プライバシー](../../PRIVACY.md)を参照してください。

生成されたノートや約束は確認が必要です。話者の識別、意味に基づく検索やベクトル検索、カレンダー連携、特定の会議サービスからの直接インポート、暗号化された音声の再生、ネイティブのシステム音声録音は未実装です。

<a id="models-and-connections"></a>

## モデルと接続

文字起こしと要約は、それぞれ別の処理です。**現在、どの要約プロバイダーを使う場合も、録音にはローカルの Whisper が必要です。** このリリースではクラウド文字起こし API を提供していません。

| 要約の処理先 | 設定 | Open Granola が送信するもの |
|---|---|---|
| 内蔵ローカル Qwen | `qwen3-4b-q4.gguf` をインストール | プロバイダーへのリクエストなし |
| LM Studio | OpenAI 互換サーバーを起動し、`http://127.0.0.1:1234/v1` と読み込んだモデルの ID を指定 | このデバイス上のサーバーへのテキスト |
| OpenAI API | 自分の API キーと対応するモデル ID | OpenAI へのテキスト。API の利用料金がかかります |
| Claude API | 自分の Anthropic API キーとモデル ID | Anthropic へのテキスト。API の利用料金がかかります |
| OpenAI 互換 | 互換性のあるベース URL、モデル ID、必要に応じてキー。例：ローカルの Ollama サーバー | 設定したサーバーへのテキスト |
| ChatGPT プラン — 実験的機能 | **ChatGPT で続行（Continue with ChatGPT）**を選び、対象プランの使用を承認してからモデルを選択 | 承認したプランを通じて OpenAI に送信するテキスト |

ChatGPT への接続には、[オープンソース・ローカルアプリ向けの公式サインインフロー](https://developers.openai.com/siwc/token-sharing-open-source)を使用します。既存の ChatGPT の会話にアクセスできるようになるわけではありません。利用資格やモデルの提供状況は、アカウントとプロバイダーによって異なります。この連携は、実際のアカウントを使った一連の動作をまだ検証していません。ここで対応するのはテキストのリクエストです。[このプレビューは音声の文字起こしには対応していません](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)。

Claude には API キーで接続します。このアプリに Claude の一般向けアカウントでログインする機能はありません。OpenAI API キーによる接続と ChatGPT プランによるサインインは、別の接続方法です。

<a id="connect-a-summarizer"></a>

### 要約モデルを接続する

セットアップガイド：[LM Studio](../integrations/LM_STUDIO.md) · [Ollama](../integrations/OLLAMA.md)。

1. デスクトップアプリで**設定 → モデルと接続（Settings → Models & connections）**を開きます。
2. プロバイダーを選択し、正確なモデル ID を入力します。カスタムサーバーの場合は、そのサーバーのドキュメントに記載された API ベース URL を入力します。
3. ChatGPT の場合は、アカウントを接続して**利用可能なモデルを読み込む（Load available models）**を選ぶか、そのアカウントで使えるモデル ID を入力します。デバイス外の送信先を使う場合は、そこへのテキスト送信を許可する設定を有効にします。この許可は、アシスタントやレシピが使用する、関連する保存済みノートにも適用されます。
4. 設定を保存し、**接続をテスト（Test connection）**を実行します。
5. 長いセッションを始める前に、短いマイク録音を行い、文字起こしとノートを確認します。

リモートのエンドポイントには HTTPS が必要です。暗号化されない HTTP を使用できるのは、`127.0.0.1` のような IP アドレスを直接指定したループバック接続だけです。LM Studio には上記のアドレスをそのまま使用してください。カスタムサーバーの互換性はテストが必要です。「OpenAI 互換」という表記だけでは、すべてのエンドポイントが同じリクエストフィールドに対応しているとは限りません。モデルが失敗しても、ローカル処理からクラウド処理へ自動的に切り替わることはありません。

キーはネイティブコードで扱い、利用できる場合は OS の認証情報ストアに保存します。そこに保存できない場合は、そのセッションのメモリ内だけに保持し、その状態を表示します。認証情報は会議データベースやブラウザストレージには保存しません。ローカルで動くサーバーでも、リクエストを別の場所へ転送する可能性があります。Open Granola がテキストを送ったあとの扱いは、そのサーバーの設定によって決まります。

<a id="try-the-preview"></a>

## プレビューを試す

<a id="browser-workspace"></a>

### ブラウザワークスペース

```sh
git clone https://github.com/anshuman-pandey/open-granola.git
cd open-granola
npm ci
npm run dev
```

ブラウザワークスペースではサンプル会議を表示します。録音、ネイティブの推論処理、プロバイダーの認証情報の保存は行いません。

<a id="desktop-development-build"></a>

### デスクトップの開発ビルド

Rust **1.98 以降**、Node **22.12 以降**（Node 24 LTS を推奨）、CMake、libclang、C/C++ コンパイラー、および [Tauri のプラットフォーム別前提条件](https://v2.tauri.app/start/prerequisites/)をインストールしてください。Linux では ALSA、WebKitGTK、設定されている PipeWire の開発用依存関係も必要です。macOS バンドルの対象は macOS 14.4 以降です。プラットフォーム向けのビルド設定があることは、実機での品質検証が完了したことを意味しません。

```sh
npm ci
npm run tauri dev
```

Tauri のフックは、アプリを起動する前にローカル推論用のヘルパーをビルドします。リリース用バンドルを作成する場合は、次を実行します。

```sh
npm run tauri build
```

ビルドの出力先は `src-tauri/target/release/bundle` です。署名、公証、インストールとアップグレードのテストは、別途必要なリリース作業です。準備ができたら、検証済みの成果物を [Releases](https://github.com/anshuman-pandey/open-granola/releases) で公開してください。この README は、ビルド済みインストーラーの提供を約束するものではありません。

<a id="install-local-models"></a>

### ローカルモデルをインストールする

設定には、実際のモデルディレクトリ `<app-data>/library/models/` が表示されます。

- 録音するには、互換性のある Whisper モデルを **`whisper-large-v3-turbo.bin`** という名前でインストールしてください。
- 内蔵の要約モデルを使う場合に限り、互換性のある GGUF モデルを **`qwen3-4b-q4.gguf`** という名前でインストールしてください。
- LM Studio やクラウドの要約モデルを使う場合も Whisper は必要ですが、内蔵 Qwen のファイルは不要です。

モデルは手動でインストールします。アプリはダウンロード、ダウンロードの再開、配布元のチェックサムの検証を代行しません。信頼できる配布元からモデルを入手し、形式とライセンスを確認してください。ファイルがない場合や無効な場合は、セットアップエラーが表示されます。

<a id="how-a-meeting-is-processed"></a>

## 会議の処理の流れ

```text
Microphone → local Whisper → saved local transcript
                                  ↓
                    selected local/server/cloud model
                                  ↓
                         notes, actions, commitments
```

マイク音声をローカルの Whisper で文字起こしして保存し、選択したローカル・サーバー・クラウドのモデルでノート、アクション項目、約束を生成します。

ノート、文字起こし、処理の詳細はローカルに保存されますが、アプリによるデータベースの暗号化は行いません。文字起こしが確定して保存されたあとに要約が失敗した場合は、保存済みの会議から再試行できます。録音内容がまだメモリ内にある段階でクラッシュした場合、この機能では復旧できません。音声は、録音ファイルへ意図的に書き出すのではなく、RAM 内に保持します。

<a id="privacy-in-plain-terms"></a>

## プライバシーの要点

- ローカルモデルが既定です。デバイス外でテキストを処理するには、プロバイダーの設定と同意が必要です。
- プロバイダーへの接続と ChatGPT サインインのため、ネイティブのネットワーク通信を有効にしています。このビルドは**OS によってネットワークから完全に隔離された環境ではありません**。
- WebView は、同梱アセットとローカルのアプリ IPC に限定されています。プロバイダーへのリクエストはネイティブコードで実行します。
- このアプリには、テレメトリや Open Granola のクラウド同期サービスは実装されていません。接続先のプロバイダーには、それぞれ独自のデータポリシーがあります。
- ローカルの記録を削除しても、プロバイダーが保持するデータ、エクスポート済みのファイル、OS のスナップショット、バックアップは削除されません。

保存、認証情報、ネットワーク、削除の詳細は、[PRIVACY.md](../../PRIVACY.md) と [SECURITY.md](../../SECURITY.md) を参照してください。

<a id="next-priorities"></a>

## 今後の優先事項

[競合調査](../COMPETITIVE_RESEARCH.md)では、関連する大規模なリポジトリ 10 件に加え、より近い製品や隣接分野の製品 7 件を調べました。優先順位は、競合の README に載っている機能の数ではなく、ユーザーが繰り返し直面する問題に基づいています。

1. 実際のモデルとプロバイダーのアカウントを使い、新規インストールからマイク録音までの一連の動作を検証する。モデルのセットアップとパッケージ化を改善する。
2. 対象プラットフォームを明確にしたテスト構成で、システム音声、デバイスの変更、音声入力が途切れていないかの確認、長時間録音を実装・検証する。
3. 決定事項とアクション項目を文字起こしの該当箇所に結び付ける。AI の推論を確定した約束として扱う前に確認できるようにする。
4. 語彙の修正、明示的な言語選択、復旧可能な長時間会議の処理を追加する。
5. 会議の記録処理が十分に信頼できるようになったあとで、選択的なテキスト共有と、アクセス範囲を限定したエージェントの利用を検討する。

これらは計画中の機能です。調査や自動テストだけで、利用者の会議環境でアプリが正常に動くことを確認できるわけではありません。
